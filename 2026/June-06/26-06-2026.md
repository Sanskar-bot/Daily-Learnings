## Part 1 — Bug: Doctor Notes Always Returning Empty

#### Root Cause #1 — `isinstance` Check on Backend Response

The `/api/doctor/notes` endpoint returned a plain list `[{...}, {...}]`.
The client code called `.get("notes", [])` on it — valid on a `dict`, but a `list`
has no `.get()`. Python silently raises `AttributeError` which was caught by a bare
`except` clause, causing `server_notes` to always fall back to `[]`.

```python
# Before — silent failure
try:
    resp = await fetch("/api/doctor/notes")
    data = await resp.json()
    server_notes = data.get("notes", [])    # AttributeError if data is a list
except:
    server_notes = []

# After — explicit isinstance guard
resp = await fetch("/api/doctor/notes")
data = await resp.json()
if isinstance(data, list):
    server_notes = data
elif isinstance(data, dict):
    server_notes = data.get("notes", [])
else:
    server_notes = []
```

#### Root Cause #2 — `note_id` Field Name Mismatch

The deduplication logic used `note["id"]` but the backend returned `note["note_id"]`.
Every note failed the dedup check and was silently dropped:

```python
# Before
existing_ids = {n["id"] for n in local_notes}         # KeyError → empty set
merged = [n for n in server_notes if n["id"] not in existing_ids]

# After — normalise both keys on ingest
def normalise_note(n: dict) -> dict:
    n.setdefault("note_id", n.pop("id", None))
    return n

server_notes = [normalise_note(n) for n in server_notes]
existing_ids = {n["note_id"] for n in local_notes}
merged = [n for n in server_notes if n["note_id"] not in existing_ids]
```

## Part 2 — Bug: Tab Rendering (`initTabs` Scope Fix)

The tab switcher in `app.js` used `querySelectorAll('[data-tab]', group)` — but
`querySelectorAll` doesn't accept a second context argument (unlike jQuery's `$(ctx).find()`).
It was searching the **entire document** relative to the group element, returning nothing
for panels that were siblings of the group, not descendants.

```javascript
// Before — wrong scope, panels never found
function initTabs(group) {
  const tabs    = group.querySelectorAll('[data-tab]');
  const panels  = group.querySelectorAll('[data-panel]');   // siblings = not found
  ...
}

// After — search parent scope for panels
function initTabs(group) {
  const parent  = group.parentElement;
  const tabs    = group.querySelectorAll('[data-tab]');
  const panels  = parent.querySelectorAll('[data-panel]');  // correct scope
  tabs.forEach(tab => {
    tab.addEventListener('click', () => {
      tabs.forEach(t => t.classList.remove('active'));
      panels.forEach(p => p.hidden = true);
      tab.classList.add('active');
      parent.querySelector(`[data-panel="${tab.dataset.tab}"]`).hidden = false;
    });
  });
}
```

Side effect: the "Access Requests → Approved" tab was showing "No pending requests"
(the pending tab's empty state) because the panel swap wasn't working. Fixed as part
of the same change — empty states now render contextually per tab.

## Part 3 — New Endpoint: `/api/doctor/active_patients`

Previously, the "Add Clinical Note" form had a free-text patient field — a doctor could
attempt to write notes for any patient, relying on a backend check to block it. The
frontend now populates a **dropdown** of only active-access patients.

```python
# portals/doctor_portal.py
@doctor_bp.route("/api/doctor/active_patients")
@_require_jwt(roles=["doctor"])
def api_active_patients():
    doctor_id = request.jwt_payload["uid"]
    rows = db.execute("""
        SELECT u.user_id, u.username, u.name, wk.expires_at
        FROM access_requests ar
        JOIN wrapped_keys wk ON wk.request_id = ar.request_id
        JOIN users u         ON u.user_id = ar.patient_id
        WHERE ar.doctor_id = :did
          AND ar.status    = 'approved'
          AND wk.expires_at > NOW()
        ORDER BY u.name
    """, {"did": doctor_id}).fetchall()
    return jsonify([dict(r) for r in rows])
```

```javascript
// Populate dropdown on note form open
async function loadActivePatients() {
  const res  = await apiFetch("/api/doctor/active_patients");
  const list = await res.json();
  patientSelect.innerHTML = list.map(p =>
    `<option value="${p.user_id}">${p.name} (@${p.username})</option>`
  ).join('');
}
```

## Part 4 — UI/UX: Active/Expired Badges & Relative Timestamps

Every approved access entry now shows a real-time badge:

```javascript
function accessBadge(expiresAt) {
  const ms  = new Date(expiresAt) - Date.now();
  const hrs = ms / 3_600_000;
  if (ms <= 0) return `<span class="badge badge-expired">Expired</span>`;
  if (hrs < 2)  return `<span class="badge badge-warning">Expires in ${Math.ceil(hrs * 60)}m</span>`;
  return `<span class="badge badge-active">Active · ${Math.ceil(hrs)}h left</span>`;
}
```

The "Active Doctor Access" stat on the patient dashboard now counts only non-expired
approvals (previously counted all approved regardless of expiry):

```sql
-- Before
SELECT COUNT(*) FROM access_requests WHERE patient_id=:pid AND status='approved'

-- After
SELECT COUNT(*) FROM access_requests ar
JOIN wrapped_keys wk ON wk.request_id = ar.request_id
WHERE ar.patient_id=:pid AND ar.status='approved' AND wk.expires_at > NOW()
```

## Part 5 — Security: Audit Log on Note Creation

```python
# server/server.py — doctor_add_note()
@app.route("/api/notes", methods=["POST"])
@_require_jwt(roles=["doctor"])
def doctor_add_note():
    doctor_id  = request.jwt_payload["uid"]
    patient_id = body["patient_id"]

    # Backend expiry check — 403 if access has expired
    active = db.execute("""
        SELECT 1 FROM access_requests ar
        JOIN wrapped_keys wk ON wk.request_id = ar.request_id
        WHERE ar.doctor_id=:did AND ar.patient_id=:pid
          AND ar.status='approved' AND wk.expires_at > NOW()
    """, {"did": doctor_id, "pid": patient_id}).fetchone()

    if not active:
        return jsonify({"error": "access_expired_or_not_granted"}), 403

    # Insert note
    db.execute("INSERT INTO clinical_notes (...) VALUES (...)", {...})

    # Audit log
    db.execute("""
        INSERT INTO audit_log (actor_id, action, target_id, meta, ts)
        VALUES (:did, 'note_created', :pid, :meta, NOW())
    """, {"did": doctor_id, "pid": patient_id, "meta": json.dumps({"note_id": note_id})})
    db.commit()
```

`visit_date` is now always set server-side (`NOW()`) — removing the client-supplied
field prevents backdating notes to appear before the access grant was issued.
