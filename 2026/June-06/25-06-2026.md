## Part 1 — JWT Structure in MedVault

Every authenticated request carries a signed JWT in the `Authorization: Bearer` header.
The payload encodes just enough to identify the caller without a database round-trip:

```json
{
  "sub":  "3f2a1b4c-...",          // user_id (UUID)
  "uid":  "3f2a1b4c-...",          // alias — used by role-specific handlers
  "role": "doctor",                // "patient" | "doctor"
  "jti":  "a8d3e...",              // unique token ID — used for blocklist lookup
  "iat":  1750800000,              // issued at (Unix timestamp)
  "exp":  1750886400               // expires at (iat + 24h)
}
```

#### Why `jti` matters

Without a `jti`, logout is impossible to enforce — a stolen token remains valid until
it naturally expires. The `jti` is a random UUID minted at login and stored in a
blocklist on logout. Every request checks the blocklist before trusting the token.

#### Signing

```python
# server/server.py
import jwt, secrets

def _get_jwt_secret() -> str:
    # Priority: env var → dedicated file → error
    secret = os.environ.get("JWT_SECRET")
    if secret:
        return secret
    secret_file = Path("server/jwt_secret.txt")
    if secret_file.exists():
        return secret_file.read_text().strip()
    # First run — generate and persist
    secret = secrets.token_hex(64)           # 512 bits
    secret_file.write_text(secret)
    return secret

JWT_SECRET = _get_jwt_secret()

def _issue_token(user_id: str, role: str) -> str:
    now = datetime.utcnow()
    payload = {
        "sub":  user_id,
        "uid":  user_id,
        "role": role,
        "jti":  secrets.token_hex(16),
        "iat":  now,
        "exp":  now + timedelta(hours=24),
    }
    return jwt.encode(payload, JWT_SECRET, algorithm="HS256")
```

The JWT secret is **separate** from the API key — an earlier version used the same
value for both, which meant a leaked API key also compromised all tokens. Fixed by
`jwt_secret.txt` being a dedicated file added to `.gitignore`.

## Part 2 — Token Validation Middleware

```python
from functools import wraps

def _require_jwt(roles: list[str] = None):
    def decorator(f):
        @wraps(f)
        def wrapper(*args, **kwargs):
            auth = request.headers.get("Authorization", "")
            if not auth.startswith("Bearer "):
                return jsonify({"error": "missing_token"}), 401
            token = auth[7:]
            try:
                payload = jwt.decode(token, JWT_SECRET, algorithms=["HS256"])
            except jwt.ExpiredSignatureError:
                return jsonify({"error": "token_expired"}), 401
            except jwt.InvalidTokenError:
                return jsonify({"error": "invalid_token"}), 401

            # Blocklist check
            if payload["jti"] in _token_blocklist:
                return jsonify({"error": "token_revoked"}), 401

            # Role check
            if roles and payload.get("role") not in roles:
                return jsonify({"error": "forbidden"}), 403

            request.jwt_payload = payload
            return f(*args, **kwargs)
        return wrapper
    return decorator
```

Usage on endpoints:

```python
@app.route("/api/doctor/notes", methods=["POST"])
@_require_jwt(roles=["doctor"])
def doctor_add_note():
    doctor_id = request.jwt_payload["uid"]   # from token, not request body
    ...
```

The doctor's identity comes from the **token**, not the request body. This prevents
a doctor from claiming to be another doctor by crafting a malicious payload.

## Part 3 — Persistent Token Blocklist

**The problem with in-memory blocklist:** if the server restarts, the blocklist is wiped.
A user who logged out before the restart can log back in with their old (not-yet-expired)
token — effectively un-logging-out.

#### Fix: JSON-backed persistence

```python
import json, threading
from pathlib import Path

_BLOCKLIST_FILE = Path("server/token_blocklist.json")
_blocklist_lock = threading.Lock()

def _load_blocklist() -> set[str]:
    """Load JTIs from disk, discarding already-expired entries."""
    if not _BLOCKLIST_FILE.exists():
        return set()
    data = json.loads(_BLOCKLIST_FILE.read_text())
    now = time.time()
    return {entry["jti"] for entry in data if entry["exp"] > now}

_token_blocklist: set[str] = _load_blocklist()   # populated at startup

def _revoke_token(jti: str, exp: float) -> None:
    with _blocklist_lock:
        _token_blocklist.add(jti)
        # Append to file atomically
        existing = json.loads(_BLOCKLIST_FILE.read_text()) if _BLOCKLIST_FILE.exists() else []
        existing.append({"jti": jti, "exp": exp})
        _BLOCKLIST_FILE.write_text(json.dumps(existing))

# Hourly cleanup job — removes expired JTIs from memory and file
def _cleanup_blocklist():
    with _blocklist_lock:
        now = time.time()
        data = json.loads(_BLOCKLIST_FILE.read_text()) if _BLOCKLIST_FILE.exists() else []
        fresh = [e for e in data if e["exp"] > now]
        _BLOCKLIST_FILE.write_text(json.dumps(fresh))
        _token_blocklist.clear()
        _token_blocklist.update(e["jti"] for e in fresh)
```

In-memory lookup stays O(1). Disk write only happens at logout and the hourly cleanup.

## Part 4 — OTP Store Persistence (Same Pattern)

The OTP flow for email-verified login had the same in-memory problem:

```python
# server/otp_store.json schema per entry
{
  "otp":      "482917",
  "expires":  1750886400.0,     # float Unix timestamp
  "attempts": 0                 # brute-force counter — lock after 5
}
```

On startup, expired entries are discarded. On send/verify/delete, the file is updated
atomically under `_otp_lock`. The `attempts` counter prevents OTP brute-forcing even
across server restarts.

## Questions I Still Have

- For multi-worker deployments (gunicorn with N workers), each worker has its own in-memory blocklist. A logout on worker 1 doesn't propagate to worker 2. The file is the source of truth but workers only re-read it at startup. Is a per-request file read too expensive? (Yes — Redis is the real answer here.)
- Should the OTP `attempts` counter reset after a successful login, or should it stay set for auditing?
- The blocklist file grows on every logout. The cleanup job runs hourly — is that frequent enough for a high-traffic deployment?
