## Part 1 — Diagnosing `no_otp_found` on `/auth/verify_sms`

After deployment, users were reporting that entering the correct OTP returned `no_otp_found`. Added OTP tracing to the endpoint to understand what was happening:

```python
# debug: add OTP tracing to diagnose no_otp_found on verify_sms
print(f"[OTP DEBUG] Looking for: phone={phone}, purpose=sms_verify")
row = db.execute(
    "SELECT * FROM otp_store WHERE phone=:p AND purpose='sms_verify'",
    {"p": phone}
).fetchone()
print(f"[OTP DEBUG] Found row: {dict(row) if row else None}")
```

**Root cause found:** The `otp_store` table didn't exist — the schema migration that was supposed to create it was failing silently because of a missing column in the `users` table (`patient_details`), which caused the entire migration transaction to roll back.

---

## Part 2 — Schema Migration Fix

The migration failure was caused by `ALTER TABLE users ADD COLUMN patient_details JSONB` running after a `CREATE TABLE otp_store` statement in the same transaction — when `ALTER TABLE` failed (column already existed on some deployments), the whole transaction rolled back including the `otp_store` creation.

**Fix:** Split the migration into idempotent individual statements with `IF NOT EXISTS`:

```sql
-- Safe regardless of state
ALTER TABLE users ADD COLUMN IF NOT EXISTS patient_details JSONB;
CREATE TABLE IF NOT EXISTS otp_store (
    id          SERIAL PRIMARY KEY,
    phone       TEXT,
    email       TEXT,
    otp_code    TEXT NOT NULL,
    purpose     TEXT NOT NULL,
    expires_at  TIMESTAMP NOT NULL,
    used        BOOLEAN DEFAULT FALSE
);
```

## Part 3 — Graceful OTP Provider Degradation

Before this fix, if `TWILIO_AUTH_TOKEN` or `EMAIL_HOST` were not set, the endpoint would raise an unhandled `RuntimeError` → 500 crash. Added explicit provider checks:

```python
def send_otp_sms(phone, otp_code):
    if not all([TWILIO_SID, TWILIO_AUTH_TOKEN, TWILIO_PHONE]):
        raise RuntimeError("SMS provider not configured")
    # ... actual send

@app.route("/auth/otp/send", methods=["POST"])
def send_otp():
    try:
        send_otp_sms(phone, code)
    except RuntimeError as e:
        return jsonify({"error": "provider_unavailable", "detail": str(e)}), 503
```

503 is the correct HTTP status here — the service exists but the upstream provider is unavailable.

## What I Practiced / Built

- Traced the `no_otp_found` bug to a cascading schema migration failure
- Fixed migration with `IF NOT EXISTS` guards on all DDL statements
- Added graceful 503 degradation for unconfigured SMS/email providers
- Learned: `get_json(force=True)` raises 400 on malformed JSON — switched to `get_json(silent=True)` which returns `None` instead, letting the app handle it cleanly

- Should migrations run at startup (entrypoint script) or be a separate manual step? Running at startup is convenient but risks running on every container restart.
