## Part 1 — Docker Deployment Configuration

Added full Docker support so MedVault can be deployed anywhere without manual environment setup:

```dockerfile
# Key decisions made in the Dockerfile:
FROM python:3.11-slim           # slim image — smaller, fewer attack surfaces
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt  # no cache = smaller layer
COPY . .

# Non-root user — running as root in a container is a security antipattern
RUN useradd -m appuser && chown -R appuser /app
USER appuser

EXPOSE 5000
CMD ["gunicorn", "--bind", "0.0.0.0:5000", "server:app"]
```

Also fixed `START.py` — it was launching Flask's built-in dev server (`app.run()`) which is not safe for production. Updated to spawn gunicorn instead.

#### Why gunicorn over Flask dev server?

| Feature | Flask dev server | Gunicorn |
|---|---|---|
| Multi-worker | ❌ | ✓ (configurable) |
| Concurrent requests | 1 at a time | Many |
| WSGI compliance | Loose | Full |
| Suitable for production | ❌ | ✓ |

## Part 2 — Production Hardening Configuration

Implemented a layered configuration system — `config.py` with three environments:

```python
class DevelopmentConfig:
    DEBUG = True
    SQLALCHEMY_ECHO = True      # shows SQL queries in terminal

class ProductionConfig:
    DEBUG = False
    SQLALCHEMY_ECHO = False
    SESSION_COOKIE_SECURE = True
    SESSION_COOKIE_HTTPONLY = True
    SESSION_COOKIE_SAMESITE = 'Lax'

class TestingConfig:
    TESTING = True
    SQLALCHEMY_DATABASE_URI = 'sqlite:///:memory:'
```

The active config is selected via `FLASK_ENV` environment variable — no hardcoded values.
