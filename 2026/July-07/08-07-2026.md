## Part 1 — Multi-Step Phone & Email Verification

Added a two-step OTP flow to the registration process:

```
Step 1: User submits name, email, phone, password
Step 2: SMS OTP sent via Twilio → user enters code → phone verified
Step 3: Email OTP sent via SMTP → user enters code → email verified
Step 4: Account activated, redirect to dashboard
```

Key implementation decisions:

- **OTP storage:** Stored in the database (`otp_store` table) with a 10-minute expiry, not in-memory — so OTPs survive server restarts (learned this lesson from MedVault v1's in-memory OTP bug)
- **Phone-only fallback:** If SMTP is not configured (`EMAIL_HOST` env var missing), the verification step is skipped for email — no 500 crash, clean 503 JSON response
- **`.env.example` updated** with all new required vars: `TWILIO_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_PHONE`, `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USER`, `EMAIL_PASS`

## Part 2 — Railway Deployment

Updated the Dockerfile for Railway's build environment:

```dockerfile
# Railway injects PORT at runtime — bind to it, not hardcoded 5000
CMD ["sh", "-c", "gunicorn --bind 0.0.0.0:$PORT server:app"]
```

Railway-specific considerations:
- `RAILWAY_ENVIRONMENT` env var automatically set — used to detect production
- PostgreSQL provisioned as a Railway plugin — `DATABASE_URL` injected automatically
- Health check endpoint added: `GET /health` returns `{"status": "ok"}` — Railway uses this to know when the container is ready

## Part 3 — Auth-Header Regression Class (Fix-Up Round 2 & 3)

During the refactor, several endpoints broke because the `Authorization` header was being read inconsistently:

**Root cause:** Some endpoints used `request.headers.get("Authorization")`, others used `request.headers.get("X-API-Key")`, and after the JWT refactor, some were still checking the old API key header.

**Fix:** Standardised all auth on a single `_require_jwt()` decorator. Any endpoint with `@_require_jwt()` reads the token from `Authorization: Bearer <token>` — no exceptions. Removed all raw header reads from route handlers.

Also added Nginx subdomain routing config so `api.medvault.app` routes to the Flask backend and `medvault.app` routes to the static HTML portals.
