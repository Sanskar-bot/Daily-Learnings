## Part 1 — Two Sum (Array / Hash Map)

**Pattern:** Hash map for O(1) complement lookup instead of O(n²) brute force.

Store each number's index as you scan. For each element, check if `target - current` is already in the map. If yes, you've found the pair.

**Complexity:** O(n) time, O(n) space.

---

## Part 2 — Group Anagrams (Hash Map)

**Pattern:** Character-count fingerprint as a dictionary key.

Anagrams have identical character frequencies. Build a 26-slot count array per word, convert to tuple (tuples are hashable, lists aren't), use as the key in a `defaultdict(list)`.

```python
count = [0] * 26
for ch in word:
    count[ord(ch) - ord('a')] += 1
grouped[tuple(count)].append(word)
```

**Why not sort?** Sorting is O(k log k) per word. The count approach is O(k) — linear per character, no sorting.

**Complexity:** O(n·k) time, O(n·k) space (n = number of words, k = max word length).

---

## Part 3 — Top K Frequent Elements (Hash Map + Sorting)

**Pattern:** Count frequencies → sort by count → take top k.

```python
freq = defaultdict(int)
for n in nums:
    freq[n] += 1
return sorted(freq, key=freq.get, reverse=True)[:k]
```

This is O(n log n). Can be improved to O(n log k) with a min-heap, or O(n) with bucket sort by frequency.

## Part 4 — Best Time to Buy and Sell Stock (Greedy / One Pass)

**Pattern:** Track the running minimum price. For each price, compute `profit = price - min_price` and update `max_profit`.

No nested loops needed — for any selling day, the optimal buy day is always the cheapest day before it.

**Complexity:** O(n) time, O(1) space.

## Part 5 — Valid Parentheses (Stack)

**Pattern:** Stack + hashmap. Closing bracket must match the most recently opened one — exactly what a stack's LIFO order gives you.

```python
pairs = {')': '(', ']': '[', '}': '{'}
for ch in s:
    if ch in pairs:
        if not stack or stack[-1] != pairs[ch]:
            return False
        stack.pop()
    else:
        stack.append(ch)
return len(stack) == 0
```

**Complexity:** O(n) time, O(n) space (worst case: all openers, like `"(((("`).

## Part 6 — Longest Substring Without Repeating Characters (Sliding Window)

**Pattern:** Two-pointer sliding window with a set to track window contents.

Move `right` forward. If `s[right]` is already in `seen`, shrink from the left until the duplicate is gone. Track the maximum window size throughout.

**Complexity:** O(n) time (each character added and removed at most once), O(min(n, m)) space (m = character set size).

---

## Part 7 — Merge Intervals (Sort + One Pass)

**Pattern:** Sort by start, then merge greedily.

After sorting, you only need to check if the next interval overlaps the current "accumulator". If `next_start <= current_end`, extend: `end = max(end, next_end)`. The `max` handles the "one interval fully inside another" case.

**Complexity:** O(n log n) time (sort dominates), O(n) space.

## Questions I Still Have

- Top K Frequent: the bucket sort O(n) approach uses an array indexed by frequency — what happens if frequencies can be larger than n? (They can't by definition, since n elements have at most n occurrences each.)
- Merge Intervals: why `max(end, next_end)` and not just `next_end`? Because one interval could be fully inside another, e.g. `[1, 10]` contains `[2, 3]` — taking `next_end` = 3 would shrink the merged interval.
