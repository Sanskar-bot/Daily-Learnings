## Part 1 — Encapsulation: What It Actually Means

Encapsulation is about **controlling access to internal state**. The object decides what outsiders can see and do — not the caller.

In Python, it's enforced by convention + name mangling:

| Prefix | Access | Meaning |
|---|---|---|
| `balance` | Public | Anyone can read/write |
| `_balance` | Protected (convention) | "Don't touch from outside" |
| `__balance` | Private (name-mangled) | `BankAccount.__balance` → actually stored as `_BankAccount__balance` |

The name-mangling gotcha: `a.__balance` raises `AttributeError` — but `a._BankAccount__balance` works. Python doesn't truly hide it; it just makes accidental access harder.

## Part 2 — Properties & Setters

Python's `@property` decorator lets you expose a read-only or validated attribute while keeping the real value private:

```python
class BankAccount:
    def __init__(self, account_num, owner, balance=0, pin=None):
        if pin is None:
            raise ValueError("PIN is required")
        self.__account_num = account_num   # private — read-only via property
        self.__balance = balance            # private — no setter (read-only)
        self.__pin = pin                    # private — never exposed

    @property
    def account_no(self):
        return self.__account_num          # read-only: no setter defined

    @property
    def balance(self):
        return self.__balance              # read-only

    @property
    def owner(self):
        return self.__owner

    @owner.setter
    def owner(self, value):
        if not value or not value.strip():
            raise ValueError("Owner name cannot be empty")
        self.__owner = value               # validated setter
```

Key insight: `@property` without a corresponding `@x.setter` makes the attribute **read-only**. Trying to set it raises `AttributeError: property 'balance' has no setter`.

## Part 3 — Private Security Fields: PIN System

Added PIN protection — private field, private helper, lockout after 3 wrong attempts:

```python
def __check_pin(self, pin):              # double underscore = private method
    if self.is_locked:
        raise Exception("Account locked")
    if pin != self.__pin:
        self.__pincounter += 1
        raise Exception("Wrong PIN")
    self.__pincounter = 0               # reset immediately on correct PIN

@property
def is_locked(self):
    return self.__pincounter >= 3
```

The `__check_pin` helper is the DRY approach — both `withdraw` and `transfer` call it instead of duplicating the lock/counter logic.

**Bug I fixed:** The original version reset the counter *after* raising the exception, which meant the counter never actually reset. Moved the reset to happen on correct PIN (before any raises).

## Part 4 — Daily Limit with Validated Setter

```python
@property
def dailylimit(self):
    return self.__dailylimit

@dailylimit.setter
def dailylimit(self, value):
    if value < 0:
        raise Exception("Limit can't be negative")
    self.__dailylimit = value

# In __init__:
self.dailylimit = float('inf')   # unlimited by default — uses the setter
```

Using `float('inf')` as the default means "no limit" without needing a special `None` check in `withdraw`. The comparison `amount > float('inf')` is always `False`, so no limit is naturally enforced.
