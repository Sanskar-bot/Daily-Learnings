## Part 1 — Sliding Window Maximum (Monotonic Deque) 🔴 Hard

**The naive approach:** Call `max()` on every window → O(n·k). With n = 100,000 and k = 50,000, that's 5 billion operations — too slow.

**The insight:** I only need the **maximum** of each window, not all elements. If I maintain a deque where the front is always the current maximum, I can answer each window in O(1).

**The monotonic deque invariant:** The deque stores indices, and the values at those indices are in **strictly decreasing** order from front to back.

```python
from collections import deque

def maxSlidingWindow(nums, k):
    out = []
    dq = deque()          # stores indices; values are decreasing front-to-back

    for i in range(len(nums)):
        # 1. Evict the front if it fell out of the window
        if dq and dq[0] <= i - k:
            dq.popleft()

        # 2. Remove all back elements smaller than nums[i]
        #    (they can never be the max of any future window)
        while dq and nums[dq[-1]] < nums[i]:
            dq.pop()

        # 3. Add current index
        dq.append(i)

        # 4. The front is the window maximum
        if i >= k - 1:
            out.append(nums[dq[0]])

    return out
```

**Why step 2 works:** If `nums[i] > nums[j]` and `i > j`, then `j` will leave the window before `i`. So `j` can never be the maximum when `i` is in the window — it's useless. Remove it now.

**Complexity:** O(n) time — each index is pushed once and popped at most once. O(k) space — the deque holds at most k indices.

## Part 2 — Two Sum II — Input Array Is Sorted (Two Pointers)

**Pattern:** Since the array is already sorted, use left and right pointers converging toward each other.

```python
def twoSum(numbers, target):
    left, right = 0, len(numbers) - 1
    while left < right:
        total = numbers[left] + numbers[right]
        if total == target:
            return [left + 1, right + 1]   # 1-indexed
        elif total < target:
            left += 1    # need bigger sum → move left pointer right
        else:
            right -= 1   # need smaller sum → move right pointer left
```

**Why it works:** The sort order means: moving `left` right can only increase the sum, moving `right` left can only decrease it. Each step eliminates one element that cannot be part of the answer.

**Complexity:** O(n) time, O(1) space — no extra data structure, just two variables.
