## Part 1 — Inheritance: What It Is

Inheritance lets a subclass **reuse** the attributes and methods of a parent class, then add or override as needed:

```python
class Vehicle:
    def __init__(self, brand, speed):
        self.brand = brand
        self.speed = speed

    def info(self):
        print(f"{self.brand} goes at {self.speed} km/h")

class Car(Vehicle):             # Car IS-A Vehicle
    def __init__(self, brand, speed, doors):
        super().__init__(brand, speed)   # delegate to parent
        self.doors = doors              # Car-specific attribute

    def honk(self):
        print(f"{self.brand} goes beep")
```

`Car` inherits `info()` from `Vehicle` — no need to rewrite it.

---

## Part 2 — Why `super().__init__()` is Critical

Without `super().__init__()`, the parent's `__init__` never runs, so the parent's attributes are never set:

```python
class Car(Vehicle):
    def __init__(self, brand, speed, doors):
        # super().__init__(brand, speed)  ← commented out (bug!)
        self.doors = doors

c = Car("Honda", 120, 4)
c.info()    # AttributeError: 'Car' object has no attribute 'brand'
```

This was the exact bug in my initial version. `self.brand` and `self.speed` never existed because `Vehicle.__init__` was never called — so `info()` crashed.

**Fix:** always call `super().__init__()` first in a subclass `__init__`, before setting subclass-specific attributes.

---

## Part 3 — `isinstance()` and the Class Hierarchy

`isinstance()` checks not just the exact class but the **entire inheritance chain**:

```python
c = Car("Honda", 120, 4)

isinstance(c, Car)      # True  — c is a Car
isinstance(c, Vehicle)  # True  — Car IS-A Vehicle, so c is also a Vehicle
isinstance(c, object)   # True  — everything in Python inherits from object
```

This is the foundation of **polymorphism**: you can write a function that accepts any `Vehicle`, and it works for `Car`, `Truck`, `Motorcycle` etc. — as long as they all inherit from `Vehicle`.

---

## Part 4 — Method Resolution Order (MRO)

Python uses the **C3 linearisation** algorithm to decide which class's method to call when there's ambiguity (especially in multiple inheritance). For the simple `Car → Vehicle → object` chain:

```python
Car.__mro__
# (<class 'Car'>, <class 'Vehicle'>, <class 'object'>)
```

Python searches left to right — `Car` first, then `Vehicle`, then `object`. `super()` means "start the search from the next class in the MRO".
